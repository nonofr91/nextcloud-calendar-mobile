# C3 — Extended Talk integration
> Scope tag: [ecosystem] | Effort: M | Targets: epic #256 | Tracking: #382

## Goal & UX
Deepen the existing Talk integration beyond "create a room from the editor":
1. **Join-in-one-tap (detect more links)** — the Join button already exists (`app/event/[uid].tsx:317-326`, `openTalkRoom` in `src/features/event/utils/openTalkRoom.ts`) but `talkUrl` is only detected when `LOCATION` contains `/call/` (`caldav-parse.ts:13,272`). Web convention (verified: nextcloud/calendar commit 7f39c7b / PR #5395) writes the Talk URL to `LOCATION` when empty, else **appends it to `DESCRIPTION`** (hybrid events); newer web also reads `CONFERENCE` (`getConferenceList()[0].uri`). Make links in `DESCRIPTION` and `CONFERENCE` detectable and tappable.
2. **"Call starts in 5 min" reminder** — extra local notification for talk-linked events whose tap opens the event (and optionally a "Join" action opening Talk directly).
3. **Resend the link to attendees** — share/mailto action on the event detail.
4. **(Optional) room metadata** — `GET /room/{token}` subtitle (displayName / participant count).

## Upstream dependencies & capability gating
- Talk API v4 `POST /room` is confirmed unchanged in Talk 24/25 (impact analysis §3.1). `GET /ocs/v2.php/apps/spreed/api/v4/room/{token}` exists for users+guests (200/404); participant list is `GET .../room/{token}/participants` (v1) and can 403 for non-moderators — verify available count field before using.
- Gating stays `capabilities.talkEnabled = 'spreed' in caps` (`nextcloud.ts:91-95`), global per **active** account (`useCapabilitiesSync.ts`). Detection of existing links must NOT depend on talkEnabled (an attendee's own server may lack Talk while the event's does).
- No new permissions; `nextcloudtalk` already in `LSApplicationQueriesSchemes` (`app.config.ts:40`), `USE_EXACT_ALARM`/`SCHEDULE_EXACT_ALARM` already declared (line 54).

## Edge cases & error handling
- Hybrid event (real `LOCATION` + link in `DESCRIPTION`/`CONFERENCE`): keep location display/map, talkUrl only feeds the Join button (step 3 fix).
- Override VEVENTs: `exceptionFields` must re-run detection so an exception with a different link overrides correctly.
- Multiple/foreign-host links: take the first; `resolveTalkAccount` already falls back exact-baseUrl → host → null (browser path still works without account).
- `talkUrl` present but Talk app absent: existing 'app'/'ask'/browser modes in `openTalkRoom` cover it.
- Notification tap on event deleted since: router push lands on "Event not found" screen — already handled in `[uid].tsx:179-196`.
- `capabilities.talkEnabled=false`: hide only creation toggle and (d) metadata; keep detection/join/share (event may come from another server).
- Room metadata 404 (room deleted): hide row silently; never block Join.
- Editing a web-created talk event: `withTalkRoom:false` (`eventToInput.ts:16`) — location/description round-trip the link untouched; ensure update path (`resolveLocationAndDescription`) never creates a second room.
