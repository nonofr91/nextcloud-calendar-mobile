# B6 — AI text features via TaskProcessing
> Scope tag: [mobile+] | Effort: L (local-template tier M) | Targets: new epic candidate | Tracking: #383

## Goal & UX
Two server-AI text features plus an always-on local template so the surfaces work with zero AI:
1. **Day summary** — sparkles entry in `CalendarTopBar` (`src/features/calendar/components/CalendarTopBar.tsx`, wired from `app/(tabs)/calendar/index.tsx`) → bottom sheet: local template renders instantly ("3 events · next: Standup 09:30, Room 1"), replaced in place by the AI summary when the task completes. Async latency (seconds) → "thinking" state.
2. **Description drafting** — sparkle button on the description field in `EventForm.tsx` (:380-390) → fills `description` state for user review; never auto-saves (uses existing `useUpdateEvent`/`useCreateEvent` path, `useMutateEvent.ts:197/227`).
3. Smart prefill (NL → event fields) deferred — overlaps D10 tier-1 intents; note only.
Tiering: local template = offline baseline (shippable alone, ~M); TaskProcessing = opt-in upgrade.
Feeds D9 tier-2 (spoken briefing): the same summary text → `expo-speech` TTS — shared seam, coordinate if both land.

## Upstream dependencies & capability gating
- `GET {base}/ocs/v2.php/taskprocessing/tasktypes` (NC30+) → `ocs.data.types` map keyed by task-type id; each has `inputShape`/`outputShape` slot descriptors `{name, description, type:int, mandatory:bool}` (+ `isInternal`, NC33+).
- `POST .../taskprocessing/schedule` `{input:<slot map>, type, appId, customId?}` → `ocs.data.task` (verify: older NC30 docs show flattened fields — handle both); errors: 400 invalid type, 412 provider unavailable, 429 rate-limited (20 req/2 min/user — docs repeat the limit on the fetch endpoint: verify whether polling shares the bucket; budget ≤~10 polls/task).
- `GET .../taskprocessing/task/{id}` → `ocs.data.task` with **`status:int`** (1 scheduled / 2 running / 3 successful / 4 failed / 5 cancelled — verify constants; D10 plan drafted string statuses — correct it there) + `output` (map|null) + `message`. Tasks purge ~1 week. `POST /task/{id}/cancel` exists.
- Text task ids: `core:text2text` and `core:text2text:summary` (input slot `input`, output `output`) — verify advertised ids + slot keys on a live server; keep the mapping data-driven, not hardcoded.
- Requires admin-installed Assistant + AI provider (OpenAI-compatible/LocalAI/Ollama). Detection = tasktypes response, **not** the capabilities endpoint → lazy `useTaskTypes()` hook cached in a store, fetched only when `aiEnabled`; do NOT extend `fetchServerCaps` (`src/services/nextcloud/nextcloud.ts:79-99`) — server-side metadata computation "can be slow", don't tax every capabilities refresh.
- Gate UI on `settings.aiEnabled` (opt-in, default off) AND ≥1 non-internal text task type; otherwise render the template tier silently.

## Edge cases & error handling
- AI absent (NC<30, empty/`isInternal`-only tasktypes) → hide entries or one-shot "AI not available on this server"; template still runs.
- 412 provider down → inline retryable error; 429 → `describeMutationError` (`errors.ts:41`) already surfaces `Retry-After`; add client cooldown before re-schedule.
- Poll 404 → task purged → offer re-run; status 4/5 → show `message`; timeout → keep template, "still thinking" hint, no auto-reschedule.
- Empty day / tasks-only day → skip schedule entirely (show template).
- Account switch or sheet close mid-poll → AbortController cleanup; task ids are per-user.
- Privacy: prompt text → server → admin-chosen provider; opt-in default-off + disclosure in settings & sheet; v1 payload excludes descriptions/attendee names (arbitration below).
- Long days → cap serialization (~30 events, truncated summaries) to fit provider context; all-day/multi-day serialization verified in `prompts.ts` tests.
- Multi-account: capability cached per `account.id` (existing per-account pattern in `useCapabilitiesSync`).
